# AGENTS.md — Meowarchive

Archive/browse site for the codemao (编程猫) community forum. Monorepo with three parts:

- `backend/` — **Python** FastAPI + SQLModel (async SQLAlchemy) + PostgreSQL, managed by `uv`, Python 3.13. The backend the frontend actually talks to.
- `goat-backend/` — **Rust** axum 0.8 + sea-orm 2.0 rewrite, under active development (current branch `feature/rustchore`). Not yet wired to the frontend.
- `frontend/` — Next.js 16 (App Router, React 19, Tailwind CSS 4, TypeScript).

## Architecture

```
frontend (Next.js RSC, port 3000)
  server components fetch http://localhost:8000/api/*   →   backend/ (Python FastAPI, port 8000)
    routers (/api/board, /api/post, /api/user, /api/reply, /api/comment)
    → SQLModel async sessions → PostgreSQL (asyncpg)

goat-backend/ (Rust, port 8080)  ← rewrite-in-progress, NOT consumed by the frontend yet
  /board, /post  → sea-orm → PostgreSQL (sqlx-postgres)
```

- Frontend pages are async Server Components that `fetch` the backend directly at render time; only pagination/jump widgets are `"use client"`.
- **`goat-backend` serves a different API shape than the frontend expects**: no `/api` prefix, pagination via `page`/`size` query params, and no `user`/search endpoints. Do not assume the frontend and Rust backend agree — they are separate workstreams.

## Build / Test / Lint

### Python backend (from `backend/`; requires Python 3.13, see `.python-version`)

```bash
uv sync                    # install deps (incl. dev group)
uv run python main.py      # dev server at 127.0.0.1:8000 with reload; loads backend/.env
uv run python -m unittest discover -s tests      # all tests
uv run python -m unittest tests.test_post_comments   # single test file
uv run ruff check          # lint
uv run ruff format         # format
```

- DB connection from `DB_URL` in `backend/.env` (untracked), format `postgresql+asyncpg://user:pass@host:port/db`. Tests are pure unit tests (DTO serialization, no live DB) and must set `os.environ.setdefault("DB_URL", ...)` before importing `app.model`.

### Rust backend (from `goat-backend/`)

```bash
cargo run        # reads .env (dotenvy): SERVER_PORT, DATABASE_URL, RUST_LOG
cargo build      # needs a recent Rust toolchain (edition 2024)
```

- Config comes from `goat-backend/.env` (untracked; `SERVER_PORT=8080`, `DATABASE_URL=postgresql://...`, `RUST_LOG=INFO`).
- Entities in `src/entity/` are generated by `sea-orm-codegen 2.0` (`@generated` headers); regenerate with sea-orm-cli, don't hand-edit schema.

### Frontend (from `frontend/`)

```bash
npm install
npm run dev                # dev server (default port 3000)
npm run build              # production build (needs live backend + DB)
npm run lint               # eslint (flat config)
npx prettier --write .     # format (prettier has no npm script)
```

No test framework is configured for the frontend.

## Key Files & Directories

### Python backend (`backend/`)
- `app/router/__init__.py` — `root = APIRouter(prefix="/api")`; includes `board`, `post`, `comment`, `reply`, `user` routers (module-level `APIRouter` with their own prefix).
- `app/router/board.py` — `GET /board/all`, `GET /board/{id}`, `GET /board/{id}/page` (paged posts; `page_size` & `page_num` required, `page_size < 50`).
- `app/router/post.py` — `GET /post/{id}`, `GET /post/{id}/replies` (defaults `page_size=30`, `page_num=1`).
- `app/router/user.py` — `GET /user`, `/user/{id}`, `/user/{id}/reply`, `/user/{id}/posts`, `/user/{id}/comments` (paged).
- `app/router/reply.py`, `app/router/comment.py` — `GET /reply/search/content`, `/comment/search/content` (backend for the frontend search page).
- `app/model.py` — SQLModel tables `User`, `Board`, `Posts`, `Replies`, `Comments`; async `engine` from `DB_URL`; `get_session` dependency.
- `app/dtos/` — `PageResult[T]` (generic `{total_page, current_page, has_prev, has_next, item}`) plus per-endpoint DTOs.
- `init.sql` — DDL for all five tables. `user` is reserved (quoted `"user"`). Drifts from models: SQL `board.description`/`posts.updated_at` have no model fields.

### Rust backend (`goat-backend/`)
- `src/main.rs` — tokio + axum entrypoint; builds `AppState { db }`, mounts `router()`, `TraceLayer` tracing, binds `SERVER_PORT`.
- `src/router.rs` — nests `/board` and `/post` (no `/api` prefix).
- `src/router/board.rs` — `GET /board`, `/board/{board_id}`, `/board/{board_id}/post`.
- `src/router/posts.rs` — `GET /post/{post_id}`, `/post/{post_id}/replies` (replies eagerly join user, then N+1-fetch comments per reply — TODO'd).
- `src/dtos.rs` — `Pagination { page, size }`, `PageResult<T> { current, total, has_next, has_prev, item }`, `PostDetail`, `PostCommentDTO`.
- `src/entity/` — sea-orm entities for the five tables.

### Frontend (`frontend/`)
- `app/types/index.ts` — **global (non-exported) interfaces** `Board`, `User`, `Post`, `Reply`, `Comment`, `PageResult`, `ReplyDTO`, `UserReplyDTO`, `UserCommentDTO`, `PostSearchItem`, etc. Do NOT add `import`/`export` here or the globals break.
- `app/page.tsx` / `board/` / `post/` / `search/` / `user/` — App Router routes; `/board/[id]` and `/post/[id]` are async pages using awaited `params`/`searchParams` Promises (Next 16 API).
- Client jump widgets: `app/board/components/JumpComponent.tsx`, `app/post/PagePostComponent.tsx`, `app/post/RepliesPostComponent.tsx`, `app/user/UserContentComponent.tsx`, `app/user/UserListPageComponent.tsx`.
- `lib/api.ts` — exports `API_BASE` (`NEXT_PUBLIC_BASE_URL` ?? `http://localhost:8000/api`).
- `next.config.ts` — `output: "standalone"` only when `NEXT_OUTPUT_STANDALONE=true` (Docker); Vercel build leaves it off.
- `frontend/AGENTS.md` — auto-generated by `next dev` for Next 16 breaking changes; points to docs in `node_modules/next/dist/docs/`. Do not delete; commit it to keep the tree clean. `CLAUDE.md` re-includes it (`@AGENTS.md`).

## Coding Conventions

- **Python**: routers as module-level `APIRouter` with `prefix`; handlers take `Path`/`Query` params + `session: AsyncSession = Depends(get_session)`; eager-load relations with `selectinload`. Return Pydantic DTOs constructed explicitly, never raw ORM objects (`GET /api/board/all` is the exception).
- **Rust**: handlers take `State<Arc<AppState>>` + `Path`/`Query`; results are `Result<Json<T>, (StatusCode, String)>`; entities are used directly as response bodies (less strict DTO discipline than Python).
- **Frontend**: async server components fetch in place (no API client layer); client components use `"use client"` + `useRouter`/`useState`. JSX formatted by Prettier; UI text is Chinese.
- Comments/TODOs in code are Chinese (`# TODO: ...`, `// TODO: ...`).
- Python tests: stdlib `unittest` classes, one concern per file.

## Known Bugs / Gotchas

- **Rust pagination flags** (fixed): `has_next`/`has_prev` were inverted in `get_board_posts_handler`, `get_all_posts`, `get_post_replies`; board's `total` also counted ALL posts. Correct semantics are `has_next: page < total_page`, `has_prev: page > 1`, and `total` filtered by board_id.
- **Rust ID type drift**: path handlers take `u32` (`post_id`) but entities use `i64`; board paths use `i64`. Inconsistent casts throughout.
- **Python `post.py`**: `has_next` uses `==` instead of `<` in `get_replies_by_post_id`; `PostDetailsDTO.n_views` is set from `res.n_comments`.
- **Missing rows crash**: Python handlers use `.one()` without error handling (unknown id → 500). Rust handlers use `.one()` and map `None` → 404, so Rust is safer here.
- **Model/SQL drift**: adding a column requires updating `init.sql`, the sea-orm entity (or regen), and the DTOs; the live DB may already differ from `init.sql`.
- **`next build` needs a live backend + DB**: the build executes page fetches.
