# AGENTS.md — Meowarchive

Archive/browse site for the codemao (编程猫) community forum. Monorepo with two independent apps:

- `backend/` — FastAPI + SQLModel (async SQLAlchemy) + PostgreSQL, managed by `uv`, Python 3.13.
- `frontend/` — Next.js 16 (App Router, React 19, Tailwind CSS 4, TypeScript).

## Architecture

```
frontend (Next.js RSC, port 3000)
  server components fetch http://localhost:8000/api/*   →   backend (FastAPI, port 8000)
    routers (/api/board, /api/post) → SQLModel async sessions → PostgreSQL (asyncpg)
```

- Frontend pages are async Server Components that `fetch` the backend directly at render time; only pagination/jump widgets are `"use client"`.
- Backend returns Pydantic DTOs (not raw models) for list/detail endpoints.

Backend modules:
- `backend/app/__init__.py` — creates `FastAPI` app, permissive CORS (`allow_origins=["*"]`), mounts root router.
- `backend/app/router/__init__.py` — `root = APIRouter(prefix="/api")`; includes board and post routers.
- `backend/app/router/board.py` — `GET /api/board/all`, `GET /api/board/{id}`, `GET /api/board/{id}/page` (paged posts; `page_size` and `page_num` are required query params, `page_size < 50`).
- `backend/app/router/post.py` — `GET /api/post/{id}`, `GET /api/post/{id}/replies` (defaults `page_size=30`, `page_num=1`).
- `backend/app/model.py` — SQLModel tables: `User`, `Board`, `Posts`, `Replies`, `Comments`; async `engine` from `DB_URL` env var; `get_session` dependency.
- `backend/app/dtos/` — `PageResult[T]` (generic `{total_page, current_page, has_prev, has_next, item}`) plus per-endpoint DTOs. Paged endpoints return `PageResult`.

Frontend modules:
- `frontend/app/types/index.ts` — global (non-exported) interfaces `Board`, `User`, `Post`, `Reply`, `Comment`, `PageResult`, `ReplyDTO` mirroring backend responses.
- `frontend/app/page.tsx` / `board/` / `post/` — App Router routes; `/board/[id]` and `/post/[id]` are async pages using awaited `params`/`searchParams` Promises (Next 16 API).
- `frontend/app/board/components/JumpComponent.tsx`, `frontend/app/post/RepliesPostComponent.tsx` — client-side page-jump widgets.

## Build / Test / Lint

Backend (run from `backend/`; requires Python 3.13, see `.python-version`):

```bash
uv sync                    # install deps (incl. dev group)
uv run python main.py      # dev server at 127.0.0.1:8000 with reload; loads backend/.env
uv run python -m unittest discover -s tests      # all tests
uv run python -m unittest tests.test_post_comments   # single test file
uv run ruff check          # lint
uv run ruff format         # format
```

- DB connection comes from `DB_URL` in `backend/.env` (untracked), format `postgresql+asyncpg://user:pass@host:port/db`. Tests are pure unit tests (DTO serialization, no live DB) and must set `os.environ.setdefault("DB_URL", ...)` before importing `app.model`.

Frontend (run from `frontend/`):

```bash
npm install
npm run dev                # dev server (default port 3000)
npm run build              # production build
npm run lint               # eslint (flat config)
npx prettier --write .     # format (prettier has no npm script)
```

No test framework is configured for the frontend.

## Key Files & Directories

- `backend/init.sql` — DDL for all five tables. `user` is a reserved word (quoted as `"user"`). Slight drift from the models: SQL `board.description` and `posts.updated_at` have no model fields; the model has no `updated_at` on `Posts`.
- `backend/main.py` — dev entrypoint; runs `uvicorn.run("app:app", ...)`.

- `frontend/tsconfig.json` — `strict: true`, `@/*` path alias, includes all `**/*.ts(x)` (this is what makes the global types in `app/types/index.ts` visible).
- `frontend/AGENTS.md` — auto-generated by `next dev` for Next 16 breaking changes; points to docs in `node_modules/next/dist/docs/`. Do not delete this block; commit it with your changes to keep the tree clean. `frontend/CLAUDE.md` just re-includes it (`@AGENTS.md`).
- `.vscode/settings.json` — local SQLTools connection (`codemao_forum` db on localhost:5432); machine-specific, not project config.
- Root `README.md`, `backend/README.md` — empty/placeholder.

## Coding Conventions

- Python: routers named `board`/`post` as module-level `APIRouter` with `prefix`; handlers take `Path`/`Query` params and a `session: AsyncSession = Depends(get_session)`; eager-load relations with `selectinload`. Returns are Pydantic DTOs constructed explicitly, never raw ORM objects for list/detail endpoints (`GET /api/board/all` is the exception).
- Frontend: async server components fetch in place (no API client layer); types are declared globally in `app/types/index.ts` — do not add `import`/`export` there or the globals break. Client components use `"use client"` + `useRouter`/`useState`. JSX formatting follows Prettier; UI text is Chinese.
- Comments/TODOs in code are Chinese (`# TODO: ...`).
- Tests: stdlib `unittest` classes, one concern per file.

## Tips for AI Agents

- **Backend API base URL**: pages fetch via the shared constant `API_BASE` in `frontend/lib/api.ts`, which reads `NEXT_PUBLIC_BASE_URL` (default `http://localhost:8000/api`, override in `frontend/.env.local`; see `.env.example`). Keep `@/lib/api` imported in every page that fetches; add a page by copying the existing fetch pattern.
- **Server-side fetch caching**: server components use bare `fetch`, so `next build` may statically render pages with stale data. If data freshness matters, add `export const dynamic = "force-dynamic"` or `cache: "no-store"`.
- **Next 16 breaking changes**: `params`/`searchParams` are Promises (must be `await`ed), `LayoutProps`/global types come from `next-env.d.ts`. Read `frontend/AGENTS.md` and the bundled docs before writing frontend code.
- **`next build` needs a live backend**: the build executes page fetches; run the backend (and a reachable DB) before `npm run build`.
- **`/api/board/{id}/page` requires both `page_size` and `page_num`** (no defaults, `lt=50` only); `/api/post/{id}/replies` has defaults (30/1).
- **Known bugs in `backend/app/router/post.py`** (current as of this writing): `has_next` uses `==` instead of `<` in `get_replies_by_post_id`, and `PostDetailsDTO.n_views` is set from `res.n_comments`. Fix deliberately, not incidentally.
- **Missing rows crash**: handlers use `.one()` without error handling; an unknown id yields a 500 rather than 404.
- **Model/SQL drift**: adding a column to a model requires updating both `init.sql` and the DTOs; the live DB may already differ from `init.sql`.
- **Prefer DTOs over raw models**: when extending an endpoint, add a DTO class in `backend/app/dtos/` rather than serializing ORM objects.
- **Ports**: backend fixed at 8000 (CORS is wide open for dev), frontend default 3000.
